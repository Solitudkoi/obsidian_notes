16.5
Consider the relations r1(A, B, C), r2(C, D, E), and r3(E, F), with primary keys A, C, and E, respectively. Assume that r1 has 1000 tuples, r2 has 1500 tuples, and r3 has 750 tuples. Estimate the size of r1 ⋈ r2 ⋈ r3, and give an efficient strategy for computing the join.


r₁(A,B,C), r₂(C,D,E), r₃(E,F). Primary keys: A, C, E respectively. n₁ = 1000, n₂ = 1500, n₃ = 750.

**Estimate the size of r₁ ⋈ r₂ ⋈ r₃:**

Since C is the primary key of r₂, and r₁ ⋈ r₂ joins on C, each tuple of r₁ matches at most one tuple of r₂. So the number of tuples in r₁ ⋈ r₂ ≤ n₁ = 1000.

Since E is the primary key of r₃, and (r₁ ⋈ r₂) ⋈ r₃ joins on E, each tuple of the intermediate result matches at most one tuple of r₃. So the number of tuples in r₁ ⋈ r₂ ⋈ r₃ ≤ 1000.

**Estimated size = 1000 tuples.**

**Efficient strategy:**

Compute (r₁ ⋈ r₂) first, then join the result with r₃. This order is efficient because r₁ ⋈ r₂ produces at most 1000 tuples (a small intermediate result). If we computed r₂ ⋈ r₃ first, the result could be up to 1500 tuples, leading to a larger intermediate relation. Since C and E are primary keys with likely indexes available, indexed nested-loop join can be used for both joins.

Let V (C,r1) be 900, V (C,r2) be 1100, V (E,r2) be 50, and V (E,r3) be 100. Assume that r1 has 1000 tuples, r2 has 1500 tuples, and r3 has 750 tuples. Estimate the size of r1 ⋈ r2 ⋈ r3 and give an efficient strategy for computing the join.


Same relations, but no primary keys (entire schema is the key). V(C,r₁)=900, V(C,r₂)=1100, V(E,r₂)=50, V(E,r₃)=100. n₁=1000, n₂=1500, n₃=750.

**Join size estimation formula:**

When R ∩ S = {A} is not a key, estimated size = n_r × n_s / V(A, r) or n_r × n_s / V(A, s), take the lower one.

**Size of r₁ ⋈ r₂ (join on C):**

- Estimate 1: n₁ × n₂ / V(C, r₁) = 1000 × 1500 / 900 ≈ 1667
- Estimate 2: n₁ × n₂ / V(C, r₂) = 1000 × 1500 / 1100 ≈ 1364

Take the lower: **|r₁ ⋈ r₂| ≈ 1364**

**Size of (r₁ ⋈ r₂) ⋈ r₃ (join on E):**

- Estimate 1: 1364 × 750 / V(E, r₁⋈r₂) = 1364 × 750 / 50 = 20,460
- Estimate 2: 1364 × 750 / V(E, r₃) = 1364 × 750 / 100 = 10,230

(V(E, r₁⋈r₂) = min(V(E, r₂), n_{r₁⋈r₂}) = min(50, 1364) = 50)

Take the lower: **|r₁ ⋈ r₂ ⋈ r₃| ≈ 10,230**

**Now check the alternative order: (r₂ ⋈ r₃) first:**

- |r₂ ⋈ r₃|: min(1500×750/50, 1500×750/100) = min(22500, 11250) = **11,250**

Then (r₁ ⋈ (r₂ ⋈ r₃)):

- 1000 × 11250 / min(V(C,r₁), V(C,r₂)) = 1000 × 11250 / 900 = 12,500

This produces a larger intermediate result (11,250 vs 1,364).

**Efficient strategy:** Compute r₁ ⋈ r₂ first (intermediate result ≈ 1364 tuples, much smaller), then join with r₃. This minimizes the size of the intermediate relation.

16.16
Suppose that a B+-tree index on (dept name, building) is available on relation department. What would be the best way to handle the following selection?
σ(building < “Watson”) ∧ (budget < 55000) ∧ (dept name = “Music”)(department)

![[Pasted image 20260520181350.png]]


B+-tree index on **(dept_name, building)** is available on relation department.

Selection: σ_{(building < "Watson") ∧ (budget < 55000) ∧ (dept_name = "Music")}(department)

Since the index is on **(dept_name, building)** and the condition includes **dept_name = "Music"** (equality on the first attribute of the composite index) and **building < "Watson"** (range on the second attribute), we can use the index to look up all entries with dept_name = "Music" and building < "Watson" directly.

This works because in a composite B+-tree index, fixing the first attribute (equality) and doing a range scan on the second attribute is exactly what the index supports efficiently.

After retrieving these tuples, we test the remaining condition **budget < 55000** in memory, since budget is not part of the index.

**Summary:** Use the composite index to retrieve tuples satisfying (dept_name = "Music" ∧ building < "Watson"), then filter by budget < 55000 in memory.

16.20

Explain how to use a histogram to estimate the size of a selection of the form
σA≤v(r).



**How to use a histogram to estimate the size of σ_{A≤v}(r):**

A histogram on attribute A divides the range of A values into several buckets, and records how many tuples fall into each bucket.

To estimate σ_{A≤v}(r):

1. Find the bucket that contains value v.
2. For all buckets entirely below v, add up their tuple counts — all these tuples satisfy the condition.
3. For the bucket containing v, assume uniform distribution within the bucket. If the bucket covers range [a, b] and contains c tuples, estimate the fraction of tuples satisfying A ≤ v as c × (v - a) / (b - a).
4. Sum up results from steps 2 and 3.

For example, suppose the histogram has buckets [0,10): 200 tuples, [10,20): 300 tuples, [20,30): 150 tuples. To estimate σ_{A≤15}(r): all tuples in [0,10) satisfy (200), plus a fraction of [10,20): 300 × (15-10)/(20-10) = 150. Estimated result size = 200 + 150 = **350 tuples**.
