### 18.2 — Adding Locks to T34 and T35

#### Adding lock/unlock instructions

Since whether B (or A) gets written depends on a runtime condition, we conservatively acquire an X lock on the item that might be written:

```
T34:  lock-S(A);
      read(A);
      lock-X(B);
      read(B);
      if A = 0 then B := B + 1;
      write(B);
      unlock(A);
      unlock(B);

T35:  lock-S(B);
      read(B);
      lock-X(A);
      read(A);
      if B = 0 then A := A + 1;
      write(A);
      unlock(B);
      unlock(A);
```

Both satisfy 2PL: all locks are acquired before any lock is released (lock points are reached after the second lock is acquired).

#### Can deadlock occur?

**Yes.** Consider this interleaving:

|T34|T35|
|---|---|
|lock-S(A) ✅||
||lock-S(B) ✅|
|lock-X(B) ❌ **wait** (T35 holds S(B))||
||lock-X(A) ❌ **wait** (T34 holds S(A))|
|💀 **Deadlock!**|💀 **Deadlock!**|

T34 holds A and waits for B; T35 holds B and waits for A — a classic circular wait.

### 18.2 — 为 T34 和 T35 添加锁

#### 添加锁定/解锁指令

由于 B（或 A）是否被写入取决于运行时条件，我们保守地对可能被写入的项获取 X 锁：

```
T34:  lock-S(A);
      read(A);
      lock-X(B);
      read(B);
      if A = 0 then B := B + 1;
      write(B);
      unlock(A);
      unlock(B);

T35:  lock-S(B);
      read(B);
      lock-X(A);
      read(A);
      if B = 0 then A := A + 1;
      write(A);
      unlock(B);
      unlock(A);
```


两者都满足 2PL：所有锁都在任何锁释放之前获得（在获得第二个锁之后达到锁点）。

#### 是否会发生死锁？

是的。请考虑这种交错方式：

|T34|T35|
|---|---|
|lock-S(A) ✅||
||lock-S(B) ✅|
|lock-X(B) ❌ **等待** (T35 持有 S(B))||
||lock-X(A) ❌ **等待** (T34 持有 S(A))|
|💀 **僵局！**|💀 **僵局！**|

T34 持有 A 并等待 B；T35 持有 B 并等待 A——经典的循环等待。
