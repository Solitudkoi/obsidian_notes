# 二、实验内容和原理

本实验的主要内容是对 BMP 图像进行读取、灰度化处理以及亮度调整。实验以 24-bit 彩色 BMP 图像作为输入，通过 RGB 与 YUV 颜色空间之间的转换，实现灰度图生成和图像亮度变化，并最终将处理后的结果重新保存为 BMP 图像。

## 2.1 BMP 图像文件格式

BMP（Bitmap）是一种常见的无压缩位图格式，文件结构主要包括以下几个部分：

1. **位图文件头（BITMAPFILEHEADER）**
   用于标识该文件是否为 BMP 文件，并给出文件总大小、图像数据起始偏移量等信息。

2. **位图信息头（BITMAPINFOHEADER）**
   用于描述图像的宽度、高度、位深度、压缩方式、图像数据大小等信息。

3. **调色板（Palette）**
   对于 8-bit 位图，需要使用调色板来表示像素值对应的颜色；而 24-bit 彩色 BMP 一般不使用调色板。

4. **图像数据（Image Data）**
   存储实际的像素信息。对于 24-bit BMP，每个像素占 3 个字节，按 **B、G、R** 的顺序存储，而不是常见的 RGB 顺序。

此外，BMP 图像的每一行数据长度必须是 4 字节的整数倍，因此当一行像素字节数不足 4 的倍数时，需要在行末补齐若干字节，这部分称为 **padding**。因此，在读取图像时不能简单按 `width * 3` 连续处理，而必须考虑每行真实占用的字节数。

---

## 2.2 RGB 与 YUV 颜色空间

RGB 颜色空间由红、绿、蓝三个分量组成，适合图像显示与存储；YUV 颜色空间则将图像信息分解为亮度分量和色度分量，更适合进行图像分析与亮度处理。

其中：

* **Y**：亮度分量，反映图像的明暗信息
* **U、V**：色度分量，反映颜色偏差信息

本实验中使用的 RGB → YUV 转换公式为：

[
Y = 0.299R + 0.587G + 0.114B
]

[
U = -0.14713R - 0.28886G + 0.436B
]

[
V = 0.615R - 0.51499G - 0.10001B
]

对应的 YUV → RGB 转换公式为：

[
R = Y + 1.13983V
]

[
G = Y - 0.39465U - 0.58060V
]

[
B = Y + 2.03211U
]

由于亮度信息集中在 Y 分量中，因此在生成灰度图时，只需要保留 Y 分量即可。

---

## 2.3 灰度图生成原理

灰度图像不再保留颜色信息，而是只保留亮度信息。因此在 YUV 空间下，可以直接令：

[
Gray = Y
]

为了增强灰度图的显示效果，本实验对 Y 值进行了最小-最大归一化处理，使所有灰度值都映射到 ([0,255]) 区间内：

[
Gray = \frac{Y - Y_{min}}{Y_{max} - Y_{min}} \times 255
]

经过归一化后，灰度图的对比度更加明显，显示效果更好。

本实验生成的灰度图采用 **8-bit BMP** 格式存储，即每个像素只占 1 个字节，同时构造 256 级灰度调色板，使灰度值 0 对应黑色，255 对应白色，中间值对应不同程度的灰色。

---

## 2.4 图像亮度调整原理

图像亮度调整在 YUV 空间中进行。由于 Y 表示亮度，因此只需要对 Y 分量进行加减即可实现图像整体变亮或变暗，而 U、V 保持不变，从而尽量保留原图颜色特征。

本实验中采用的方法为：

* 调亮：
  [
  Y' = Y + 50
  ]

* 调暗：
  [
  Y' = Y - 50
  ]

为了防止计算结果越界，需要将新的亮度值限制在 ([0,255]) 范围内。亮度调整完成后，再将新的 YUV 数据转换回 RGB，得到最终输出的彩色 BMP 图像。

# 三、实验步骤与分析

## 3.1 定义 BMP 文件结构体

程序首先定义了 BMP 文件头、信息头、图像结构体和 YUV 结构体。为了保证结构体与 BMP 文件中的字节布局完全一致，程序使用了：

```c
#pragma pack(1)
```

这样可以避免编译器自动插入对齐字节，确保 `fread` 和 `fwrite` 读写 BMP 头部时不会出错。

其中：

* `BITMAPFILEHEADER` 对应 BMP 文件头
* `BITMAPINFOHEADER` 对应 BMP 信息头
* `BMPImage` 用于保存当前图像的头信息、宽高、padding 和像素数据
* `YUVImage` 用于保存转换后的 Y、U、V 三个分量

这种结构化设计使得后续函数之间传递数据更加清晰，也便于分模块实现各项功能。

---

## 3.2 读取 BMP 文件

在 `read_bmp()` 函数中，程序先以二进制方式打开文件：

```c
FILE *file = fopen(filename, "rb");
```

然后分别读取文件头和信息头：

```c
fread(&img->fileHeader, sizeof(BITMAPFILEHEADER), 1, file);
fread(&img->infoHeader, sizeof(BITMAPINFOHEADER), 1, file);
```

为了保证输入文件符合实验要求，程序进一步进行了三项检查：

1. `bfType == 0x4D42`，判断文件是否为 BMP；
2. `biBitCount == 24`，限定输入为 24-bit 彩色 BMP；
3. `biCompression == 0`，限定输入为未压缩 BMP。

接着，程序计算每行末尾需要补齐的 padding：

```c
img->padding = (4 - (img->width * 3) % 4) % 4;
img->line_size = img->width * 3 + img->padding;
```

这里的 `line_size` 表示图像每一行在文件中实际占用的字节数。之后程序根据 `bfOffBits` 定位到像素数据起始位置，并将整幅图像的像素数据读入内存。这样后续所有图像处理都可以直接在内存中完成，提高了程序处理效率。

---

## 3.3 生成 8-bit 灰度图

灰度图生成函数 `write_gray_bmp_8bit()` 是本实验中的关键部分之一。与简单地把 24-bit 图像改成“R=G=B”的伪灰度图不同，本实验实现的是**真正的 8-bit 灰度 BMP**。

首先，程序构造新的文件头和信息头，将位深度改为 8 位：

```c
grayInfoHeader.biBitCount = 8;
grayInfoHeader.biClrUsed = 256;
grayInfoHeader.biClrImportant = 256;
```

并重新计算 8-bit 位图每行的字节数和整幅图像的数据大小：

```c
int grayRowSize = (img->width + 3) & ~3;
int grayDataSize = grayRowSize * img->height;
```

接下来，程序第一遍遍历原图像，计算每个像素对应的亮度 Y，并记录最小值 `minY` 和最大值 `maxY`。这一步是后续归一化的基础。然后构造 256 项灰度调色板，使得调色板中第 `i` 项的 RGB 值都等于 `i`，从而表示从黑到白的 256 级灰度。

在第二遍遍历中，程序再次计算每个像素的亮度值，并进行归一化：

```c
BYTE gray = (BYTE)((Y - minY) * 255.0f / range);
```

最终将归一化后的灰度值写入新的 `grayData` 数组中，并按照 8-bit BMP 格式依次写出文件头、信息头、调色板和灰度图像数据。这样生成的 `gray.bmp` 不仅视觉上是灰度图，而且文件格式上也是标准的 8-bit 灰度位图。

---

## 3.4 申请 YUV 空间并完成 RGB → YUV 转换

为了对亮度分量进行单独操作，程序设计了 `YUVImage` 结构体，并通过 `alloc_yuv()` 为 Y、U、V 三个数组动态分配内存。之所以使用 `float` 类型，是因为 YUV 转换中会出现小数，并且 U、V 可能为负值，因此不能用 `BYTE` 存储。

在 `rgb_to_yuv()` 函数中，程序逐像素读取原图的 B、G、R 值。由于 BMP 采用 BGR 顺序存储，因此代码中通过：

```c
BYTE r = pixel[2];
BYTE g = pixel[1];
BYTE b = pixel[0];
```

获取正确的 RGB 值。随后按照转换公式计算出对应的 Y、U、V，并存入 `yuv->Y[idx]`、`yuv->U[idx]` 和 `yuv->V[idx]`。这样，彩色图像就被转换到了 YUV 空间，便于后续只对亮度分量进行调节。

---

## 3.5 改变亮度分量 Y

亮度调节由 `change_luminance()` 函数完成。该函数遍历所有像素，对每个像素的 Y 分量加上一个常量 `delta`：

```c
yuv->Y[i] += delta;
```

当 `delta` 为正时，图像整体变亮；当 `delta` 为负时，图像整体变暗。为了避免亮度值超出合法范围，程序又加入了边界限制：

```c
if (yuv->Y[i] < 0) yuv->Y[i] = 0;
if (yuv->Y[i] > 255) yuv->Y[i] = 255;
```

本实验中分别取 `delta = 50` 和 `delta = -50`，生成调亮图和调暗图。由于只修改了 Y 分量，而 U、V 保持不变，因此图像的颜色关系能够大体保持，只是整体亮度发生改变。

---

## 3.6 YUV → RGB 转换并恢复彩色图像

在 `yuv_to_rgb()` 中，程序将修改后的 YUV 数据转换回 RGB。转换完成后，为避免浮点运算结果超出像素范围，程序定义了 `clamp()` 函数，将所有结果限制在 ([0,255]) 区间内：

```c
BYTE clamp(float value)
{
    if (value < 0) return 0;
    if (value > 255) return 255;
    return (BYTE)value;
}
```

随后再按 BMP 的 BGR 顺序写回图像数据：

```c
pixel[2] = r;
pixel[1] = g;
pixel[0] = b;
```

经过这一步处理后，内存中的图像数据重新变为可以直接保存的 24-bit 彩色 BMP 数据。

---

## 3.7 输出 BMP 图像

彩色图像输出由 `write_bmp()` 完成。该函数重新打开输出文件，并依次写入文件头、信息头和像素数据。由于彩色图仍然是 24-bit BMP，因此不需要写调色板，只需要保证 `imageData` 按照原有格式完整写出即可。

本实验最终生成三张结果图像：

* `gray.bmp`：8-bit 灰度图；
* `light.bmp`：亮度增强后的彩色图；
* `dark.bmp`：亮度减弱后的彩色图。

这样就完成了从读取、转换、处理到输出的完整实验流程。

---

## 3.8 主程序流程分析

主函数 `main()` 将整个实验流程组织为三个相互独立的处理过程：

1. 读取原图并生成灰度图；
2. 重新读取原图并生成调亮图；
3. 再次读取原图并生成调暗图。

之所以每次都重新读取原图，而不是在上一结果图上继续处理，是为了避免不同处理步骤之间相互影响。例如，如果先生成灰度图再继续做亮度调整，就会丢失原图中的彩色信息。因此，重新读取原始输入图像是更稳妥、更合理的实现方式。

在程序结束前，主函数分别调用 `free_bmp()` 和 `free_yuv()` 释放动态申请的内存，避免内存泄漏。这也体现了程序设计中对资源管理的考虑。
