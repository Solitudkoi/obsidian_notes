# ✏️【三、实验步骤与分析（段落版 · 推荐直接替换）】

## 3.1 BMP 文件结构体设计

本实验首先根据 BMP 文件的结构定义了相关数据结构，包括 `BITMAPFILEHEADER`、`BITMAPINFOHEADER` 以及用于存储图像信息的 `BMPImage` 结构体。同时，为了保证结构体在内存中的排列方式与 BMP 文件的实际存储格式一致，程序使用了 `#pragma pack(1)` 取消结构体对齐，从而避免在读写文件时产生错误。此外，还定义了用于存储 YUV 分量的结构体 `YUVImage`，为后续颜色空间转换提供数据支持。

---

## 3.2 BMP 图像读取

在读取 BMP 图像时，程序首先通过 `fopen` 以二进制方式打开文件，然后使用 `fread` 分别读取文件头和信息头。为了确保输入图像符合实验要求，程序对文件类型、位深度以及压缩方式进行了检查，例如判断 `bfType` 是否为 “BM”，以及 `biBitCount` 是否为 24 位。随后，根据图像宽度计算每一行的实际字节数，并考虑行对齐（padding）问题：

```c
padding = (4 - (width * 3) % 4) % 4;
line_size = width * 3 + padding;
```

由于 BMP 图像按行存储，且每行长度必须为 4 字节的倍数，因此必须通过 `line_size` 来正确访问像素数据。最后，程序通过 `fseek` 定位到图像数据起始位置，并将整幅图像读入内存。

---

## 3.3 灰度图生成

灰度图生成是本实验的核心步骤之一。程序采用两遍扫描的方法完成灰度化处理。首先，在第一遍遍历中，对每个像素计算其亮度分量：

```c
Y = 0.299R + 0.587G + 0.114B;
```

并记录整幅图像中的最小值 `minY` 和最大值 `maxY`。随后，在第二遍遍历中，对每个像素的亮度值进行归一化处理，使其映射到 ([0,255]) 区间：

```c
Gray = (Y - minY) * 255 / (maxY - minY);
```

为了使灰度图符合标准 BMP 格式，程序将其存储为 8-bit 位图，并构造 256 级灰度调色板，使调色板中每一项的 RGB 值相同，从而表示不同亮度的灰色。同时，还需要重新计算图像大小以及文件偏移量，并在写入文件时依次写入文件头、信息头、调色板和图像数据。

---

## 3.4 RGB 与 YUV 颜色空间转换

为了实现亮度调节，程序首先将图像从 RGB 空间转换到 YUV 空间。在实现过程中，需要注意 BMP 图像的像素存储顺序为 BGR，因此在读取像素时需要重新排列通道顺序。转换公式如下：

```c
Y = 0.299R + 0.587G + 0.114B;
U = -0.14713R - 0.28886G + 0.436B;
V = 0.615R - 0.51499G - 0.10001B;
```

转换后的 Y、U、V 分量分别存储在独立的数组中，便于后续单独对亮度分量进行操作。

---

## 3.5 图像亮度调整

在 YUV 空间中，亮度信息由 Y 分量表示，因此程序通过对 Y 分量加上一个常量来实现图像亮度的调整：

```c
Y = Y + delta;
```

其中，当 `delta > 0` 时图像变亮，当 `delta < 0` 时图像变暗。为了防止亮度值超出合法范围，程序对结果进行了边界限制：

```c
if (Y < 0) Y = 0;
if (Y > 255) Y = 255;
```

本实验分别设置 `delta = 50` 和 `delta = -50`，从而得到调亮和调暗后的图像。

---

## 3.6 YUV 转 RGB 及图像恢复

在完成亮度调整后，程序需要将图像从 YUV 空间转换回 RGB 空间。转换过程中同样需要注意浮点计算可能带来的越界问题，因此程序定义了 `clamp` 函数，将结果限制在 ([0,255]) 范围内。转换后的 RGB 值再按照 BMP 的 BGR 顺序写回图像数据中，从而恢复为标准的 24-bit 彩色图像。

---

## 3.7 图像写入与程序流程

在图像写入阶段，程序分别生成三种结果图像：灰度图、调亮图和调暗图。灰度图采用 8-bit BMP 格式写入，需要额外写入调色板；而调亮和调暗图仍为 24-bit 彩色 BMP，只需写入文件头、信息头和像素数据即可。

主函数中，程序分别三次读取原始图像并进行不同处理，而不是在同一图像上连续操作。这种方式可以避免不同处理步骤之间的相互影响，从而保证每一张输出图像都是基于原始数据生成的。此外，程序在结束前释放所有动态分配的内存，保证程序运行的稳定性。
