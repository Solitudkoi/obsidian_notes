Bonus 1 :
LRU-K 题目简述：维护两个链表 History 和 Cache，依次读入 m 个数。 
如果一个数既不在 History 也不在 Cache 那么就将他放入 History 末端。
如果这个数已经在 History，并且这是第 k 次 hit 这个数，那将他移出 History、清零 hit 次数并放入 Cache 末端；否则将这个数移到 History 末端并增加一次 hit 次数。 
如果这个数已经在 Cache，那么将他移到 Cache 的末端。 
每次操作完，如果 History 或者 Cache 长度大于 n，则将第一个数移除并清空他的 hit 次数。 

bonus1可以用一个数组来记录每个元素对应的链表节点的地址，有效缩短查找时间

可能出现的问题： 
1. 时间超限：需要用可维护前驱/后继的链表 or 双向链表来实现代码，不能用数组模拟链表，这样复杂度是平方级别的。 
2. 答案错误：未及时清空 hit，一个数无论是因为 History 长度超过 n，还是因为被转移到 Cache，只要被移出了 History，都需要清空一次 hit 的次数。
	一组数据： 
	3 3 6 
	3 1 2 4 3 3 
	错误输出： 
	2 4 
	3 
	正确输出 
	2 4 3 
	-
Bonus 2 : Replacement Selection 
题目简述（原题的描述比较莫名其妙，这里直接叙述题目需要你实现的功能）：
维护若干个 runs。初始 id 为 1. 
首先将前 m 个数依次扔进第一(id = 1)个 run，然后对 m+1~n 个数分别处理： 
设当前数为 x，第 id 个 run 的最小值是 y，对比 x 和 y 的大小 
如果 x 比 y 大，则将 x 放进 id 对应的 run 里面（也就是题目中的 current run） 
如果 x 比 y 小，则将 x 放进 id+1 对应的 run 里面（也就是放进 next run） 
每次操作完后，如果编号为 id 的 run 不存在数了，那么让 id++，也就是继续使用下一个 run 。 
最后按大小顺序输出每个 runs 曾经出现过的数。 一个小tip：可以对于每个 run 都用一个（Heap）来实现，避免时间超限。
