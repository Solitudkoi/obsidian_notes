-  In the following part, I will focus on attention, which is actually the main source of this bottleneck.

- 1First, let’s understand the problem.  
	In autoregressive decoding, attention is mainly dominated by **GEMV operations**, which have very low arithmetic intensity. At the same time, the model needs to repeatedly access large **key and value matrices**.  
	As a result, attention is not limited by computation, but by **memory bandwidth**

- 2Now, based on this observation, let’s look at how attention is executed traditionally. 
	On GPUs, KV data must be moved back and forth between DRAM and the compute units. This creates a long data path and makes off-chip bandwidth the main bottleneck.
	- To address this issue, AttAcc changes the execution paradigm.  
		Instead of moving data to the compute units, it executes attention **directly inside memory**. This keeps KV matrices close to where the computation happens and avoids unnecessary data movement.

- 3Next, let’s see how attention is mapped onto PIM hardware.  
	Attention can be decomposed into three steps:  
	first, computing scores with Q times K transpose;  
	then applying Softmax;  
	and finally generating the context by multiplying with V.  
	In PIM, the two GEMV steps are executed inside DRAM banks, while Softmax is handled in the buffer layer.

- 4This leads to a very efficient dataflow.  
	The query enters memory, while K and V remain in DRAM throughout the execution. Only the final result is returned to the processor.  
	So most of the KV data never leaves memory.

- 5 Finally, this is why attention benefits greatly from PIM.  
	Its computation pattern matches well with DRAM-level parallelism, and more importantly, PIM minimizes data movement, which is the real bottleneck of attention.

- So in summary, attention is not a compute problem, but a data movement problem, and PIM directly addresses this challenge.
